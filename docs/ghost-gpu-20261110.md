## ISO setup

Applications → **Configurar Ghost na GPU**. One owner-triggered first setup
automatically downloads and hash-verifies the engine, Node runtime and model,
detects a discrete Vulkan GPU, creates a private key, starts two user services,
checks unauthenticated401 and real inference through both engine and Ghost API,
then writes the private native-shell profile. Reopen the native SolOS shell.
No manual endpoint/key/model typing. Subsequent logins start the provisioned
services, not another download. No credentials or model weights baked into ISO.

Requires a working GPU driver and internet for first setup (~2.6GB),3.5GB free,
and enough RAM/VRAM for the4B model with4096 context. Prefer an installed system
or persistent live USB. The setup does not install drivers, reboot, partition,
grant shell access to the model, or change approval policy. Lack of a supported
GPU stops setup explicitly; CPU is available only via `solos-ghost-setup --install --cpu`.
VirtualBox's emulated display is not the physical NVIDIA GPU. Physical Linux
GPU/driver acceptance requires booting the notebook into Linux, not just a VM.

Existing manual or explicitly disabled Ghost profiles are preserved, not
silently overwritten. A distinct Linux user is suitable for a clean lab.
`solos-ghost-setup --check` is read-only. Stop only these local services with:
`systemctl --user disable --now solos-ghost-api.service solos-ghost-local.service`.
Native **Remove saved setup** disconnects chat but does not remove weights or
stop a service. Do not claim removal of the profile also stops the GPU engine.

## Packaging strategy

The additive lab image can be derived from the verified8506a00 ISO without
recompiling unchanged Qt/Rust binaries: extract its exact squashfs into a NEW
directory, add only this reviewed userspace setup/source/units/launcher, require
the4 already-installed Vulkan/runtime packages, run installed-layout checks,
recompress and replay original BIOS/UEFI boot metadata into a NEW ISO.
This is a reproducible derivative/repack, not a claim that build-iso.sh was rerun.
The normal full-build hook also installs these files on a future fresh build.

Do not replace prior ISO/build trees or saved VMs. Require final squashfs GUI
comparison/smokes, ISO/checksum verification and a NEW guest boot. The new guest
can verify setup availability and honest no-GPU handling; notebook GPU throughput
above was measured on Windows, not claimed as an in-guest Linux measurement.
